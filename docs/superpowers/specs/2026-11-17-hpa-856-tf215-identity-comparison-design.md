## Decision and alternatives

Treat TF2.15 as a distinct experimental candidate and measure its drift on five
fixed full-mix inputs. The checkpoint remains the same model, while the
execution implementation has a different identity. This answers whether the
single-fixture divergence persists on realistic inputs before deciding how to
integrate a Docker-free backend.

| Approach | Tradeoff and decision |
| --- | --- |
| Require exact TF1 parity before any further measurement | Keeps the original parity gate, but does not measure whether the observed differences affect realistic outputs. Retain the gate as evidence, rather than make bit-level debugging the next project. |
| Distinct TF2.15 candidate with bounded drift measurements | Selected continuation: preserves the baseline and gives the next decision evidence at limited cost. |
| Register a production backend and run the corpus immediately | Defers identity and drift questions into production artifacts. Keep this downstream of the bounded comparison. |

The existing evidence establishes 78 restored tensors and repeatable
`oracle_divergent` output within each host. GitHub and Colab differ in event-0
confidence. Neither lock equality nor within-host repeatability establishes
cross-host bit equality. The cause of the binary64 differences is unproven.

### Probe and task-order contract

`runtime_identity.py` keeps all top-level imports in the standard library.
Use postponed annotations and `TYPE_CHECKING` imports for project types;
import descriptor helpers lazily inside host-only functions. Its `--probe`
path must not import `src`, `runtime`, TensorFlow or another third-party
package. Launch `[python311, "-s", runtime_identity.py, "--probe"]` with the
same `_worker_environment()` dictionary as the model worker.

The probe emits one JSON diagnostic with schema `crux.oaf-tf215-probe/v1`:
`status=ok` exits 0; an unsupported platform/interpreter or unavailable
required field emits `status=blocked`, reason codes and available fields,
then exits 2. Normalize x86 `flags` and ARM `Features`; retain ARM implementer,
part and revision when available. Linux aarch64 therefore emits a useful
blocked-platform record rather than a missing-x86-field traceback. The
collector preserves a blocked record; no runtime fingerprint or model worker
is created from it.

Make `driver_files` a required parameter to `build_runtime_identity()`.
Task 1 tests it with relative paths in temporary trees, so it needs no
`selected_compare.py` stub. Task 3 supplies the complete live file set listed
above; incomplete or missing live files fail before inference.

Every comparison invocation receives a new UUID `execution_id`. Store outputs
under
`artifacts/experiments/oaf-tf215/selected/<descriptor_sha256>/<runtime_sha256>/<execution_id>/`.
Carry the descriptor, runtime, both hashes and execution ID in the comparison
record. Recollect the interpreter/host probe and recompute the runtime
fingerprint after measurement; fail if it changed. There is **no prediction
reuse or resume across invocations**, even when fingerprints match. Input and
checkpoint caches remain read-only inputs
with their existing verifiers. A future production integration must include
runtime identity in its inference/cache key before enabling prediction reuse;
designing that integration is outside this phase.

Keep the existing `oaf-tf215-compare/v2` smoke record unchanged. The selected
comparison wraps its result and actual `ready.backend_id` as baseline protocol
metadata; neither is the candidate's authoritative descriptor. Do not relabel
old measurements with an identity that was not collected for them.

### Event adapters and precision

`baseline_native_events(artifact: PredictionArtifact)` unwraps
`artifact.prediction.events[*].native` into a `tuple[NativeEvent, ...]`.
The artifact parser reads decimal JSON, then converts time/confidence to
floats in `_mapped_event_from_record()`; these values retain only the
archived six-decimal precision, not native TF1 binary64 evidence.

`candidate_native_events(events: tuple[SmokeOracleEvent, ...])` decodes the
big-endian binary64 hex fields with `struct.unpack(">d", bytes.fromhex(...))`
and passes reconstructed payloads through `_decode_native_event()` to return
the same `NativeEvent` tuple type. Retain the original `SmokeOracleEvent`
arrays for exact repeatability; test adapter round trips with
`_event_from_native()`. `compare_events()` consumes the two adapted native
tuples. It does not accept mapped events or hex-valued events directly.

Preserve raw TF2.15 events, then use `quantize_six()` on time/confidence for
the comparable archived-precision view of both sides.
For ordered equality, sort that view by the existing prediction-v2 sort key:
`(time, native_class_id, bin, note, velocity, confidence)`, with absent numeric
values represented by `-1` only in the sort key. Preserve original order in
the raw binary64 record. A tie-order change from quantization must not masquerade
as a changed event set. If distinct candidate events collide on the rounded
sort key, preserve their multiplicity and original indexes, record collision
groups/counts, and continue the row. Do not invoke the production renderer's
duplicate-key rejection or deduplicate the experimental events.

### Strict agreement and one-frame diagnostics

Report counts by native class, event additions/removals, ordered equality of
all native fields at archived precision, and timing/confidence/velocity drift.
For drift pairing, adapt each event to `BenchmarkEvent`, retaining original
event index and metadata, and use existing `score_events()` with native class
ID as its matching class, tolerance **0.001 seconds**, offset **0.0**. Pair at
archived precision. Retain those strict matched/unmatched counts unchanged.
This measures near-identical predictions; strict timing statistics alone do
not measure frame displacement.

Then run `score_events()` only on the strict-unmatched events, with the same
class/zero-offset policy and a tolerance of **`512 / 44100 + 0.000001`
seconds**. The frozen runtime's
[`frame_time_seconds(1)`](../../../runtime/oaf_tf1/model.py#L264) is about
**11.61 ms**:
`configs.py` sets `hop_length=441`, but the frontend reads the inherited
`spec_hop_length=512` in `data.hparams_frames_per_second()`. The additional
1 microsecond covers the difference-rounding bound of two six-decimal times;
it is a diagnostic boundary, not a parity epsilon.

Call these residual matches `frame_shift_candidates`, with original event
indexes and signed time deltas. They indicate a possible correspondence
within one emitted frame, rather than prove the cause or physical event
identity. Report their timing statistics separately from strict pairs, and
report remaining additions/removals. Preserve both strict and residual
counts: each side's strict-unmatched count equals its frame-shift-candidate
count plus its remaining unmatched count. Reuse the existing matcher's stable
greedy tie behavior and never reuse a strict match in the second pass.

Report signed and absolute time/confidence deltas, maximum, median and p95
absolute deltas, and counts of note/bin/group/velocity changes separately for
strict pairs and frame-shift candidates. Do not zip arrays after an insertion.
Use null statistics when no pairs exist; confidence comparisons require both
values present and count missing values separately. Keep full counts and raw
events; cap only example deltas at eight.

Produce `selection.json`, `smoke.json`, `native-events.jsonl` (all 15 song
attempts on a complete run) and `comparison.json` with schema
`crux.oaf-tf215-selected-comparison/v1`. Include baseline and candidate
identities, all five row outcomes, repeatability, measurement precision,
both pairing policies, collision diagnostics, unmatched counts and metrics.
A completed measurement exits 0 even when it finds drift; blocked, invalid,
failed or non-repeatable measurements exit
nonzero after writing diagnostics. Exit 0 does not mean scientific acceptance.

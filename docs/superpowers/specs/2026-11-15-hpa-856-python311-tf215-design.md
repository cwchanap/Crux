# HPA-856 — Python 3.11 / TensorFlow 2.15 Compatibility Prototype

**Issue / delivery:** [HPA-856](https://linear.app/cwchanap/issue/HPA-856/run-the-oaf-benchmark-pipeline-on-colab-without-docker). This design belongs to the **replacement draft PR** for the Python 3.11/TF2.15 prototype; the earlier [PR #35](https://github.com/cwchanap/Crux/pull/35) is superseded/closed by explicit request. Implementation and evidence stay on this replacement PR.
**Revision:** 2026-11-15; baseline `main=f5e0d18261f32cf9fdc623b0d1a4cacaf21d686a`.
**Status:** Plan only. No Python 3.11/TF2.15 installation, graph, checkpoint restore, or inference has passed yet.

## Decision and scope

The replacement PR is **planning-only at creation**. It starts from current `main` with only these two documents and does **not** carry the prior PR's Git history or superseded Python 3.7 plan.

The user selected a bounded Python **3.11 / tensorflow-cpu 2.15.1** compatibility prototype. Selectively adapt the existing drum inference path using pinned upstream Magenta changes; do not rewrite the network in Keras or install the whole Magenta package.

This revision **supersedes** the Python 3.7.16 retry, the blanket “no TF2 port” constraint, and the proposed production `CRUX_OAF_NATIVE_PYTHON` integration. The TF1 Docker runtime remains an untouched scientific baseline. The old design's reviews do not constitute approval of an untested TF2 runtime.

The immediate deliverable is a reproducible experiment answering: can the current checkpoint restore and transcribe under TF2.15, is the output repeatable, and does it match the frozen oracle exactly? The eventual HPA-856 goal (Docker-free corpus/separation/MLflow on Colab) remains, but is a **conditional continuation on this replacement PR**, not work to implement before that answer. Finishing the prototype alone does not complete HPA-856.

### Alternatives considered

| Approach | Decision |
| --- | --- |
| More Python 3.7 provisioning attempts | Superseded by the selected direction; keep the failure as history, not a prerequisite. |
| Selective TF2.15 compatibility backport | Selected: retains graph/checkpoint/frontend and reuses upstream helpers. |
| Full current-TF/Keras rewrite, model conversion, or a new container stack | Deferred: more changes before learning whether the retained model works. |

TF2.15 is an **Estimator compatibility bridge**, not a claim of modern long-term TensorFlow architecture. TensorFlow documents that `compat.v1` does not restore `contrib` and that 2.15 is the last Estimator release [S1–S3].

## Minimal experimental surface

Use one isolated directory, `experiments/oaf_tf215/`, with `requirements.in`, a generated `requirements.lock`, `build_runtime.py`, `probe.py`, `patches/tf215-compat.patch`, `README.md`, and a short `RESULTS.md`. Put focused tests in `tests/runtime/test_oaf_tf215_probe.py`. One path-filtered CI workflow validates the isolated environment and graph without checkpoints or service credentials.

No changes to `src/`, `runtime/oaf_tf1/`, the Dockerfile, root dependencies, production CLI/registry, prediction/report schemas, or MLflow in this phase. No generic launcher framework, production adapter, duplicate scorer, GUI, training, or GPU work.

### Environment and reproducibility

Run an isolated **Python 3.11** interpreter, not Colab's notebook kernel or Crux's Python 3.12 project environment. Record the exact Python patch version/build used by the successful solve. Initial candidate pins are:

- `tensorflow-cpu==2.15.1`, `tensorflow-estimator==2.15.0`, `keras==2.15.0`, `tf-slim==1.1.0`, `protobuf==3.20.3`;
- `numpy==1.23.5`, `librosa==0.8.1`, `numba==0.57.1`, `llvmlite==0.40.1`, `scipy==1.10.1`, plus the audio/MIDI dependencies in the investigation candidate.

These are **starting candidates, not a proven lock**. Resolve on the target Python, run dependency checks, then commit a generated hash-locked environment and prove a clean reinstall from it. Do not copy the TF1 lock or alter it. Add dependencies only for a demonstrated drum-import requirement. In particular, test Slim batch normalization before assuming a `tf-keras` package fixes its legacy-layer path; any narrowly required fix is pinned and recorded, not an open-ended version search.

Launch with `CUDA_VISIBLE_DEVICES=-1`, `PYTHONHASHSEED=0`, and `TF_ENABLE_ONEDNN_OPTS=0` before TensorFlow import; call `tf.disable_v2_behavior()` before creating objects. Record these settings. They control the experiment, **not guarantee parity**. Do not apply toy-graph thread limits silently to full-model parity runs. Use normal environment separation/cleanup, not a new sandbox/attestation system.

### One builder, no edits to the frozen tree

`build_runtime(repo_root: Path, output_root: Path) -> Path` returns the generated `runtime/` directory under a fresh scratch root. Its CLI takes `--repo-root` and `--output-root`.

1. Copy the retained model/worker/config and pristine Magenta source to scratch `runtime/` and `upstream/`. Keep the original sequence converter in `upstream/` unchanged.
2. Create the `runtime/` parent but leave `runtime/vendor` **absent**; invoke `apply_reviewed_patch()` to create the instrumented vendor tree. Its existing source/patch hash validation stays intact.
3. Apply one checked-in, reviewed compatibility patch to the scratch copy. It contains selective upstream helper additions/import changes and copied-model startup/path adaptations, with upstream reference/license attribution. Do not replace the whole vendor tree or alter the original instrumentation patch.
4. Preserve the drum configuration, variable scopes, checkpoint names, Librosa mel/decibel frontend, `spec_hop_length`, thresholds, velocity/time/confidence extraction, and the instrumented-vs-pristine decoder check. `hop_length` is not a substitute for `spec_hop_length`.
5. Fail explicitly if a patch does not apply; use a new scratch root instead of reapplying to a previous experiment. Cleanup only owned temporary directories, never the source checkout or checkpoint cache.

This builder lives in the experiment, **not** in `OafBackend`. Production helper refactors are unnecessary until integration is justified.

### Probe stages and results

Adapt the supplied diagnostic probe into a standalone Python 3.11 script. Keep its environment-only mode and optional `--runtime-root --checkpoint-dir --fixture --oracle` mode. All model inputs must be supplied together, using absolute paths. Do not invoke the production `smoke-backend`, whose old cache/default-runtime behavior is unrelated to this experiment.

Execute in increasing cost order:

1. Validate Python/TF versions, graph mode and Estimator symbols; **execute** a Slim Conv2D + batch-normalization graph and a legacy LSTM graph.
2. Build/import the adapted drum configuration and graph; report missing symbols at this boundary before downloading or scoring a corpus.
3. Verify fixture SHA and every checkpoint component against the original configuration. Restore the model with existing coverage checks: 130 checkpoint tensors, 78 inference tensors, 52 classified non-inference tensors; preserve required names/shapes/dtypes and reject missing/mismatched/uninitialized weights. Count alone is not proof.
4. Run the canonical WAV twice using one loaded model and once in a fresh process. Retain the full native events, compare candidate-to-candidate repeatability, and compare each result to the frozen oracle's exact field representation.

Diagnostic JSON records the Crux commit, upstream reference, compatibility-patch and dependency-lock hashes, Python/package versions, fixture/checkpoint digests, environment settings, per-stage outcome, tensor coverage, event counts, full event output path/digest, and bounded field-level differences. No timestamps/host paths become benchmark identities.

Use distinct outcomes: `environment_only_passed`, `failed` (with failed stage), `runs_divergent`, `non_repeatable`, or `smoke_exact`. Track `inference_completed`, `repeatable`, and `oracle_exact` separately; unexecuted fields are null, not true. Exit 0 only for the explicitly requested environment gate or repeatable exact smoke; divergent/non-repeatable/model failures return nonzero **after saving diagnostics**. Authentication/network inability is a blocked experiment, not an incompatible-model claim.

Compare the complete native-event sequence, including binary64 confidence/time, pitch/class/group and velocity. The existing oracle definition remains authoritative. A stdlib comparator in this isolated Python environment is permitted only if fixture tests pin it to that contract; do not import the entire Crux application merely for comparison. Do not set an approximate epsilon, rewrite the golden, or use matching F1 as an exact-parity pass.

## Decision gate and deferred integration

| Evidence | Next action |
| --- | --- |
| Environment/graph/restore failure | Stop at the named stage and record a reproducible blocker. No backend/corpus work. |
| Inference completes but is not repeatable | Investigate the recorded difference; no promotion or cache reuse. |
| Repeatable inference, oracle differs | Useful migration evidence, **not** drop-in equivalence. Quantify differences; specify a distinct runtime/descriptor/cache identity before any production evaluation. Do not auto-accept a quality regression. |
| Repeatable exact smoke | Eligible for selected-song diagnostics and a separately planned broad comparison; one fixture does not prove corpus equivalence. |

Every experiment writes only under a separate `artifacts/experiments/oaf-tf215/` root (ignored data). Never publish candidate predictions under the frozen TF1 identity or reuse its prediction/run cache, even if one fixture matches. `model.json` is an input describing the retained weights, not authorization to label TF2 output as the TF1 backend.

At the gate, update these same docs and PR with measured results and the chosen integration contract. Do not create another implementation PR, mark HPA-856 complete, or implement both potential production architectures speculatively. The existing model/weights may stay the same while execution provenance changes.

## Acceptance and completion boundaries

**Prototype evidence milestone (automated checks, no human sign-off criterion):**
- A clean Python 3.11 environment installs from its recorded lock; real graph executions pass, not import-only checks.
- The generated drum graph restores all required checkpoint tensors without changing the source/weights/golden; two same-process requests and a fresh-process request produce stored native events and an exact comparison result.
- A deliberate fixture/checkpoint mismatch is rejected before inference; a one-ULP confidence change, missing event, and reordered event cannot pass exact comparison.
- Successful, divergent, non-repeatable and failed-stage outcomes are distinguishable; experiment outputs cannot be mistaken for canonical benchmark artifacts.
- The real target-Colab probe produces these results using the dedicated interpreter. Report “blocked” if target execution is unavailable; CI alone is not Colab proof.
- Existing TF1/Docker files remain unchanged and the existing test suite regresses cleanly. Linux environment/graph coverage runs in CI; no separate Linux/Android acceptance campaign.

**Scope completion:** the immediate spike can deliver a conclusive blocker/divergence report without pretending migration succeeded. Integration remains gated; full HPA-856 completion requires the later corpus/pilot/publication criteria. Existing curated review decisions are workflow inputs, not human acceptance criteria.

**UI/platform applicability:** this phase is a command-line runtime experiment, not an iOS/macOS/Windows application or new notebook UI. No UI mockup is attached to HPA-856; visual UI acceptance is not applicable here. Do not add device test matrices or art/SFX work.

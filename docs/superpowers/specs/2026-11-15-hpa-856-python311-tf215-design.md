# HPA-856 — Python 3.11 / TensorFlow 2.15 Compatibility Prototype

**Issue / delivery:** [HPA-856](https://linear.app/cwchanap/issue/HPA-856/run-the-oaf-benchmark-pipeline-on-colab-without-docker). This design belongs to **[replacement draft PR #36](https://github.com/cwchanap/Crux/pull/36)** for the Python 3.11/TF2.15 prototype; the earlier [PR #35](https://github.com/cwchanap/Crux/pull/35) is superseded/closed by explicit request. **Revision:** 2026-11-15; baseline `main=f5e0d18261f32cf9fdc623b0d1a4cacaf21d686a`.
**Status:** Plan only. No Python 3.11/TF2.15 installation, graph, checkpoint restore, or inference has passed yet.

## Decision and scope

The replacement PR is **planning-only at creation**. It starts from current `main` with only these two documents and does **not** carry the prior PR's Git history or superseded Python 3.7 plan.

The user selected a bounded Python **3.11 / tensorflow-cpu 2.15.1** compatibility prototype. Selectively adapt the existing drum inference path using pinned upstream Magenta changes; do not rewrite the network in Keras or install the whole Magenta package.

This revision **supersedes** the Python 3.7.16 retry, the blanket “no TF2 port” constraint, and the proposed production `CRUX_OAF_NATIVE_PYTHON` integration. The TF1 Docker runtime remains an untouched scientific baseline. The old design's reviews do not constitute approval of an untested TF2 runtime.

The immediate deliverable is a reproducible experiment answering: can the current checkpoint restore and transcribe under TF2.15, is the output repeatable, and does it match the frozen oracle exactly? The eventual HPA-856 goal (Docker-free corpus/separation/MLflow on Colab) remains, but is a **conditional continuation on this replacement PR**, not work to implement before that answer. Finishing the prototype alone does not complete HPA-856.

### Alternatives considered

| Approach | Decision |
| --- | --- |
| More Python 3.7 provisioning attempts | Superseded by the selected direction; keep the failure as history, not a prerequisite. |
| Selective TF2.15 compatibility backport | Selected: retains graph/checkpoint/frontend and reuses upstream helpers. |
| Full Keras rewrite, model conversion, or `src/app/tf2_magenta_model.py` | Rejected as an immediate shortcut: the app implementation only supports H5 checkpoint loading, not the original TF1 checkpoint, and does not preserve the model graph. |

TF2.15 is an **Estimator compatibility bridge**, not a claim of modern long-term TensorFlow architecture. TensorFlow documents that `compat.v1` does not restore `contrib` and that 2.15 is the last Estimator release [S1–S3].

## Minimal experimental surface and execution host

**First execution host:** GitHub Actions `ubuntu-24.04`, **Linux x86-64**, matching the frozen TF1 Docker image's `linux/amd64` target. **Do not** resolve or test parity on an Apple-silicon/macOS ARM64 host; `tensorflow-cpu==2.15.1` has no macOS ARM64 wheel. **Confirmation host:** authenticated Colab CPU Linux x86-64 with the identical environment and commands. A source audit, unrun CI or disconnected browser is not model evidence.

Use `uv python install 3.11` and `uv venv --python 3.11` for the worker. Keep Crux and the comparison driver in Python 3.12. Compile the **Linux target**, rather than silently selecting the developer host platform:

```bash
uv pip compile --python-version 3.11 \
  --python-platform x86_64-manylinux_2_17 --generate-hashes \
  experiments/oaf_tf215/requirements.in \
  -o experiments/oaf_tf215/requirements.lock
```

Starting candidates, **not a validated lock**: `tensorflow-cpu==2.15.1`, `tensorflow-estimator==2.15.0`, `keras==2.15.0`, `tf-slim==1.1.0`, `protobuf==3.20.3`, `numpy==1.23.5`, `librosa==0.8.1`, `numba==0.57.1`, `llvmlite==0.40.1`, `scipy==1.10.1` plus demonstrated audio/MIDI dependencies. A **fresh CI runner** installing the resulting lock with `uv pip sync --require-hashes` is the clean-install proof; do not add a redundant manual second environment. Test actual Slim batch-norm and LSTM graph sessions. Investigate a potential `tf_keras.legacy_tf_layers` failure before pinning extra packages.

Set `CUDA_VISIBLE_DEVICES=-1`, `PYTHONHASHSEED=0` and `TF_ENABLE_ONEDNN_OPTS=0` before TensorFlow import. Use `tensorflow.compat.v1` and `disable_v2_behavior()` before graph creation. These are controls for parity, not guarantees.

### Execution guardrails from November 16 re-review

The [latest design re-review](https://github.com/cwchanap/Crux/pull/36#pullrequestreview-5916545262) says **Ship**, with three valid, non-blocking corrections:

- **Prune unused eager imports in the scratch compatibility patch.** Vendored `magenta/common/__init__.py` imports `.nade.Nade` (and thus `tensorflow_probability`), `magenta/music/__init__.py` imports `notebook_utils` (and thus `bokeh`, `IPython`, `pandas`), while `configs.py` imports the unused piano `model` and `CONFIG_MAP["onsets_frames"]` (pulling old CuDNN/Contrib symbols). Trim these *only in* `patches/tf215-compat.patch`, retaining every import needed by `CONFIG_MAP["drums"]`. Verify the generated drum config and worker import under Python 3.11. Do not bulk-add unused packages to `requirements.in`, or modify frozen TF1 vendored source.
- **Sanitize the inherited worker environment.** Host Python 3.12 must call existing `src.benchmark.backends.idm._isolated_worker_environment()`, then overlay `CUDA_VISIBLE_DEVICES="-1"`, `PYTHONHASHSEED="0"`, `TF_ENABLE_ONEDNN_OPTS="0"`, `NUMBA_CACHE_DIR="/tmp/numba-cache"`. Passing `env` replaces the whole subprocess environment, so preserve needed host `PATH`, `HOME`, and `TMPDIR` (when present) while removing inherited `PYTHONPATH` and `PYTHONHOME`. Set `PYTHONHASHSEED` before process startup; the worker's `-s` does not ignore `PYTHONPATH`. Do not refactor IDM into a new shared helper just for this experiment.
- **Run the scoped tests in draft PR CI.** Existing `.github/workflows/ci.yml` skips draft PRs. As implementation lands, new `oaf-tf215-probe.yml` PR CI must execute the stdlib builder tests, build scratch, check the Python 3.11 drum import, run `graph_check.py`, and run Python 3.12 `uv run pytest -q tests/benchmark/test_oaf_tf215_compare.py`. Keep automatic PR checks free of checkpoint downloads; the manual full-model dispatch is separate.

## Result and decision gate

One source of truth: nullable `inference_completed`, `repeatable`, `oracle_exact` plus `failed_stage` and a blocker reason when execution is unavailable. Derive the label via one pure `classify_result()`; **do not store a second independently mutable outcome enum**. Name repeatable-but-not-oracle-equal **`oracle_divergent`** (not the ambiguous `runs_divergent`).

| Result | Meaning and next step |
| --- | --- |
| `failed` with stage | Dependency, graph or checkpoint failure; stop |
| `blocked` | Cannot reach host/network/checkpoint; not proven incompatible |
| `environment_only_passed` | Slim/RNN graph ran, but no checkpoint or inference claim |
| `non_repeatable` | Two same-worker or fresh-worker outputs disagree; investigate |
| `oracle_divergent` | Three outputs repeat but differ from the TF1 oracle; quantify drift, define a distinct runtime/descriptor/cache identity before integration |
| `smoke_exact` | Three outputs repeat and match original oracle; proceed to selected-song then broad comparison, not immediate production promotion |

A `smoke_exact` result alone constitutes model parity success; `environment_only_passed` is success **only for the graph command**. Divergent model mode records diagnostics and exits nonzero for the parity gate. Never rewrite original oracle, model lock, canonical predictions or identity.

Keep **one PR #36 for HPA-856** as requested. The review proposed merging the prototype and opening another PR for conditional continuation; **do not split without user approval**. Instead, at Task 6 commit `RESULTS.md` and the integration decision as an internal **review checkpoint in the same PR**, then plan only the supported continuation there. HPA-856 is not complete when the prototype alone has an answer.

Conditional future work, **not now**: authoritative reference identity, isolated selected-song/full-mix runs, existing reviewed subset, same-machine Spleeter/HTDemucs pilot, frozen separator companions, Drive resume and merged HPA-86 MLflow publication. The broad baseline is `599033663ca3bb495d8faaac13180206eaafadb4:evidence/oaf-broad/` (320 total, 182 success, 138 quarantined, raw 50 ms F1 0.234846). Its reference hash is `96c9971b2c9113e72cb293862badcc88d9146e689ea329f45576d7fb7349f041` and timing version `sha256:10868dfb1f87490692d28f6f115dfa164f20be69247115be52a76ef59c954fcf`. Do not require old cohort IDs or identity-bearing report byte equality from a different runtime identity; compare scientific values with provenance explicit.

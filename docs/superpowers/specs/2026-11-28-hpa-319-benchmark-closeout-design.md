### Fixed reviewed membership when changing anchor

Recover the actual accepted HPA-327 manifest and completed review ledger first, not just the unreviewed candidate slate (or the score-ranked HPA-856 samples). Freeze original accepted simfile IDs and decisions independently of scores. HPA-327's scorer checks reference/timing hash **and version**; its prepare/finalize continuation can carry unchanged source rows but redraw replacements, so blindly invoking it on B can change membership. Do not redraw, substitute, or edit old manifest headers.

On B, use the existing canonical reference/timing loaders, mapping preflight and candidate stream to inspect the original fixed IDs only. Verify each accepted song remains eligible and its selected chart/audio keys and content hashes, BGM alignment, timing events and mapping/review-relevant provenance are unchanged or explicitly revalidated. Matching chart/audio bytes alone do not prove unchanged derived timing. When old timing/review evidence is missing or changed, re-audit those fixed members under the original HPA-327 criteria before accepting them; record the actual additional review cost and provenance (no invented decisions or timestamps). If accepted membership cannot be recovered, a member is missing/ineligible, or the original review cannot be established/revalidated, mark the reviewed path blocked; do not reduce or redraw membership using score information.

Prefer the existing prepare/finalize continuation only when its resulting accepted IDs are exactly the original accepted IDs and all accepted decisions are substantiated; do not select new includes. If the deterministic slate cannot express that fixed set, use one documented one-time invocation of existing `build_candidate_stream`, completed-review validation, ledger/manifest row renderers and manifest publication rails, taking candidates only by the frozen accepted IDs (no maintained helper/CLI, no weakened loader or changed selector). Publish a new ledger and manifest with actual new generated fields, old ledger provenance and review evidence; verify exact member-set equality, canonical load, lineage and downstream reviewed scoring. If the existing contracts cannot represent the result honestly, stop and record the blocker instead of hand-editing generated fields. Pilot membership is separately frozen; if lineage changes, validate the original IDs and same exact input identities before rerunning/rebinding under B.

## Publication decision (predeclared)

* **All four scopes valid:** use the existing HPA-329 Task 0A/0B and strict `publish-paired-comparisons`; require all four real pairable-count keys, nonempty reviewed/separation diagnostics (not broad diagnostics), matching canonical MuScriptor lock, full populations and usable nonzero intersections. Retain the IDM `reviewed_subset_cross_verified == false` caveat unless the actual validator supports a different result. Only then publish the existing final findings path with exactly one evidence-based recommendation, and verify its numeric appendix.
* **Pilots blocked after bounded recovery/attempt, full mix valid:** publish broad OaF vs MuScriptor via existing `compare-oaf-muscriptor` and typed cohort reports; publish reviewed absolute and paired results using the existing reviewed commands and optional `--subset-manifest` only when the fixed subset validates. If reviewed evidence is itself blocked, explicitly label broad-only and why. A real positive paired intersection and lock/run equality are required. Use a clearly titled **interim** Markdown findings file (not the final HPA-329 report), including all available validated scopes separately, raw/aligned distinctions, actual exclusion/population counts, and specific reproducible pilot/subset blockers with parent acceptance items still outstanding. Do not fake zero-count runs or call this a full comparative decision. Existing per-scope comparator(s) can publish any independently valid pilot. No changes to required HPA-562 flags, request/schema, or closed headline matrix; the existing full-mix comparator already solves the partial case.
* **Full mix itself blocked:** record validated standalone evidence and precise blockers in the ledger; do not publish comparative metrics or recommend a winner without evidence.

Partial findings are useful even while the full epic remains open. The parent allows documented scope removals/blocker reports, but removing a required experiment changes the requested benchmark: do not silently waive it or mark the whole epic Done. If pilots remain infeasible, the interim result plus the ledger gives a concrete basis for an explicit reduced-scope decision; until such disposition is recorded the PR remains draft and parent open. A separately authorized scope change would require updating the report/acceptance contract, not weakening the HPA-562 publisher.

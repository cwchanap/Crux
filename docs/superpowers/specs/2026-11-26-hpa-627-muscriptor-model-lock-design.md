## Freeze identity and execution host

Use MuScriptor v0.3.0 (MIT code; source commit `d73147e75e5b9b0c0a79ebe154587db4fd603e0c`), medium checkpoint `MuScriptor/muscriptor-medium`, revision `f32236969308476e01fd3aae67357de5feb05a2d`, weight license CC BY-NC 4.0. The review reports public HEAD still equals that revision; recheck immediately before the authenticated freeze. If HEAD differs or the exact intended bytes cannot be obtained, stop and reassess rather than add a speculative revision selector or silently substitute a checkpoint.

**Proposed HPA-395 corpus host:** Linux x86-64 Colab GPU, preferably a T4-class GPU, Python 3.12 with the existing locked MuScriptor extra, explicit `cuda` / `float32` (the existing CUDA auto-dtype default). This is the selected cost-conscious target, not a claim of verified GPU availability. The existing lock resolves Torch 2.2.2's Linux x86-64 CUDA wheel and CUDA dependencies; this is installation evidence, not a successful runtime probe. Complete and test the offline acquisition/CLI changes before provisioning the GPU; verify the actual CUDA runtime, package, memory and disk before publishing anything. The lock's device/dtype are enforced by the backend and enter the run identity; do not freeze against incidental Mac MPS or CPU hardware. The freeze itself may run on another host with the explicit target values. The real smoke must run on the intended corpus host; record GPU/runtime, elapsed transcription time and RTF. This is a feasibility signal, not a full-corpus runtime projection. If the target is unavailable or medium is impractical, stop with evidence; HPA-395 permits a separate pre-score feasibility decision, never an automatic variant or dtype switch.

The existing freeze script already verifies package/license/metadata, downloads both files by exact revision, hashes actual bytes, publishes canonical JSON, reloads and verifies it. Stage the result under ignored artifacts, check the selected revision/variant/device/dtype and record the lock SHA before publication. No redundant verifier implementation or new lock fields.

## Reusable consumer preparation

Extend the existing `crux benchmark prepare-backend` command rather than add another CLI or ask every fresh Colab host to copy a heredoc.

- In `src/benchmark/checkpoint_acquisition.py`, extract the existing HF byte download into one MuScriptor-specific helper, with lazy optional HF import and sanitized acquisition failure. Preserve the HF exception as the cause and include a bounded HTTP status (e.g. 401 vs 403, if available) in the safe error message; do not copy raw credential-bearing exception text or suppress the useful cause. Freeze uses that helper and existing immutable publication to obtain bytes *before* the lock exists. A locked consumer cannot be the freeze entrypoint because checkpoint hashes do not yet exist.
- Add `prepare_muscriptor_checkpoint(lock, checkpoint_dir, *, download)`, returning the verified **directory**, not the weight-file path. Verify-only calls the existing `verify_muscriptor_checkpoint` without importing HF or networking. Before download mode performs any network call, reject a symlink/non-directory destination and inspect both target files: existing files must match locked length/SHA-256, including config, and only genuinely absent files are eligible for restoration. Download missing files using the lock's exact repo/revision/filenames, check their bytes before immutable publication, and finally verify the pair. Existing mismatches fail without overwrite; partial legitimate downloads may resume. Normalize `MuscriptorModelLockError` (from checkpoint verification), publication errors (`ArtifactPublicationError`, an `OSError`) and directory/file `OSError` to `CheckpointAcquisitionError` at this boundary; keep the original lock loader outside the acquisition boundary. No new generic cache framework, schema or streaming overhaul.
- `prepare-backend --backend muscriptor [--download]` loads the lock before acquisition (lock load/selection failure: `integrity_failed`, exit 2; checkpoint/acquisition failure: `acquisition_failed`, exit 1; ready: exit 0 with directory path). Put the two default paths and small MuScriptor path resolvers in `muscriptor_model.py`, reused by the CLI, backend and corpus runner. Retain the corpus runner's repo-anchored canonical model-lock default (`runtime/muscriptor/model.json`) so invocation outside repo root cannot select an unrelated default lock; retain CWD-relative `artifacts/muscriptor/checkpoint`. Both `CRUX_MUSCRIPTOR_MODEL_LOCK` and `CRUX_MUSCRIPTOR_CHECKPOINT_DIR` treat unset/empty as default, nonempty paths as supplied (relative to CWD if relative). Explicit `--cache-root` overrides the checkpoint env/default in the CLI. This is a deliberate resolution of today's divergent defaults rather than a third copy; tests can set explicit env fixture paths. Reject `--archive` for MuScriptor. Preserve OaF's existing default cache root, option behavior and JSON summary; no registry expansion or schema change.
- Add offline acquisition tests and focused CLI dispatch/option tests, including characterization of OaF default/explicit roots, mutually exclusive options and invalid backend; distinguish malformed lock from missing/corrupt checkpoint and publication failure. Test no HF import in verify-only, directory return, fail-before-download and shared path resolution. Commit a direct canonical-lock test in the same change as the real lock; do not add a skip that would mask a missing lock.

No credentials or gated weight/config bytes are committed. CI stays offline. No estimate or claim of successful authentication until measured.

The fresh-checkout acceptance exercises the actual consumer CLI using one GPU environment (reuse the same absolute `UV_PROJECT_ENVIRONMENT` and rebind the editable project to the fresh worktree; `uv run --no-sync` throughout smoke so optional packages remain installed), then `create_backend()` against the repository's existing `tests/fixtures/oaf_tf1_smoke/canonical.wav`, using `load_direct_audio`. The OaF oracle demonstrates drum activity on this fixture, but MuScriptor's response is not known until execution. Zero hits fail this event-path acceptance, not proof of model accuracy or grounds to retune. Record wall time/RTF, not F1. HPA-395's five-case, repeatability and broad-scoring obligations remain downstream.

No full corpus rerun, new scorer, training, separation, MLflow, UI, new infrastructure or second PR. No backend or runner changes beyond adopting shared path resolution; no inference schema, model dependency constraints or OaF runtime change.
